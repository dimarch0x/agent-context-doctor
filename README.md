# Agent Context Doctor

Линтер файлов контекста ИИ-агентов: проверяет `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`,
`SKILL.md` и каталоги правил `.agents/rules/*.md` / `.claude/rules/*.md` против
реального репозитория и находит то, что ломает работу агентов.

Python 3.10+, только стандартная библиотека, без внешних зависимостей.

## Зачем

По исследованию [Xu & Wu (2026, arXiv:2610.30571)](https://arxiv.org/abs/2610.30571),
при расхождении инструкций с кодом агенты следовали устаревшим правилам в 90,1%
решений (Claude Code явно замечал конфликт в 79 прогонах из 80, но всё равно
подчинялся старому правилу). По анализу 441 репозитория в работе
[Denisov-Blanch et al. (ASE 2026, arXiv:2608.25241)](https://arxiv.org/abs/2608.25241),
73,8% файлов AI-конфигурации коммитятся один раз и больше не обновляются.
Проблема не в модели, а в том, что правила никто не проверяет.

## Что проверяет

| Проверка | Что ловит | По умолчанию |
|---|---|---|
| `dead-path` | путь в правилах, которого нет на диске | error, если каталог существует |
| `dead-command` | `npm/pnpm/yarn/bun run X`, `make X`, `python3/php x`, которых нет | warning |
| `version-drift` | версия проекта/стека (`pyproject.toml`, `package.json`, `CLAUDE.md` ↔ `AGENTS.md`) | warning |
| `skill-frontmatter` | нет frontmatter, `name` ≠ каталог, битые ссылки на `scripts/` | error / warning |
| `duplicate-rule` | одно правило в нескольких файлах — разойдётся | info |
| `rule-conflict` | противоречия между файлами инструкций проекта (полярность и стек) | warning |
| `empty-dir` | каталог из правил существует, но пуст (0 файлов внутри) | warning |

Серьёзность выводится из факта, а не из догадки: файл пропал из существующего каталога —
ошибка; каталог не существует, но предок есть — предупреждение; не существует ничего,
путь явно предписано создать перед токеном или это кластер примеров в несуществующих
каталогах — заметка.

## Установка и запуск

```bash
pip install .                        # или запуск без установки: python3 -m agctx
python3 -m agctx scan .              # текущий каталог
python3 -m agctx scan ~/skills       # корпус скиллов и AGENTS.md
python3 -m agctx scan . --json       # машинный вывод
python3 -m agctx scan . --check dead-path --check skill-frontmatter
python3 -m agctx scan . --no-info
python3 -m agctx scan . --fix --dry-run  # предпросмотр безопасных исправлений
python3 -m agctx scan . --fix            # применить безопасные исправления
```

Коды возврата: `0` — чисто, `1` — только предупреждения, `2` — есть ошибки, `3` — путь не найден.
Удобно вешать в CI: ошибки валят сборку, предупреждения нет.

## Результаты на живых корпусах (ноябрь 2026)

| Корпус | Файлов | Ошибок | Предупреждений | Заметок | Время |
|---|---|---|---|---|---|
| Локальный корпус скиллов | 16 | 0 | 9 | 36 | ~0,15 с |
| Крупное монорепо (`hermes-agent`) | 223 | 13 | 189 | 554 | ~1,0 с |
| Рабочие проекты (`rules/` + скиллы) | 96 | 0 | 3 | 67 | ~0,15 с |

До настройки правил серьёзности то же монорепо `hermes-agent` давало 188 ошибок и
568 предупреждений — почти всё это были API-роуты, примеры структуры проекта и пути
чужих машин. Шум убирался правилами, а не списком исключений.

Пример находки:

```
ERR  [dead-path] skills/network-diagnostics/SKILL.md:115
     — путь не существует: ~/.config/kioslaverc
```

## Тесты

```bash
python3 -m unittest discover -s tests -t . -v
```

59 тестов: разбор многострочного YAML frontmatter, формальная грамматика путей, блоки кода,
все 7 проверок (включая `rule-conflict`, `empty-dir`, `GEMINI.md` и `rules/*.md`), кластеры
примеров, `--fix`, коды возврата и JSON.

## Как отдать агенту

Инструмент рассчитан на цикл «скан → разбор → утверждение → правка». `--fix` безопасно
закрывает только три класса (имя скилла, явный `version-drift`, `foo.py` → `scripts/foo.py`);
всё остальное требует решения человека: пустой путь может создаваться в рантайме, а
«противоречие» — быть намеренным.

Готовый промпт для агента (Claude Code, Antigravity, Pi, DSH, Hermes — любой с доступом к shell):

```
Ты проверяешь файлы контекста ИИ-агентов линтером и чинишь только подтверждённые проблемы.

ИНСТРУМЕНТ
Путь: <путь к agent-context-doctor>
Запуск из его каталога:
  python3 -m agctx scan <проверяемый путь> --json     # машинный вывод
  python3 -m agctx scan <путь> --fix --dry-run        # что будет исправлено
  python3 -m agctx scan <путь> --fix                  # применить безопасные правки
  python3 -m unittest discover -s tests -t .          # тесты самого линтера

ПОРЯДОК
1. Прогнать scan и показать мне сводку: сколько ошибок, предупреждений, заметок.
2. Разобрать findings по классам:
   - реально сломано (путь исчез из существующего каталога, команда не выполняется,
     правила противоречат друг другу, каталог в правилах пуст);
   - требует моего решения (файл создаётся в рантайме, путь другой машины, пример);
   - шум эвристики.
3. Для «реально сломано» предложить диффы, каждый с одной строкой обоснования.
4. Не применять ничего, пока я не скажу «применяй».
5. После применения: повторить scan, показать цифры до и после, прогнать тесты линтера.

ОГРАНИЧЕНИЯ
- Не менять код линтера и его тесты ради того, чтобы прогон стал зелёным.
- Не создавать файлы в домашнем каталоге и не править пути наугад.
- Не трогать файлы, не относящиеся к находкам, и не делать коммитов без моего слова.
- Если находку не удалось подтвердить — сказать об этом прямо, а не «исправить» наугад.

ОТЧЁТ
Список подтверждённых находок с путями и строками, диффы, цифры до/после, вывод тестов.
```

## Ограничения

- Проверяются только пути в инлайн-коде (обратные кавычки), не в прозе и не в code-fence.
- `rule-conflict` использует детерминированные эвристики полярности и конфликтующих стеков (без LLM).
- Кеширование выполняется в памяти на время одного прогона (`--fix` и повторный прогон выполняются без межсессионного дискового кеша).
